## Issues found and corrected

- Starting Docker Desktop and enabling Ubuntu-22.04 WSL integration restored
  client/server connectivity before local builds.
- The initial Debian runtime and older Nginx base failed the strict image gate.
  Updating the distribution bases, applying available Alpine security fixes and
  excluding unused runtime installers produced the passing scan above. Tests were
  rerun after the distribution switch.
- Alpine uses musl. When a stopped Redis container disappeared from Docker DNS,
  resolver delays exceeded HTTP readiness budgets even with short socket
  timeouts. Container DNS retry/timeout settings now bound that lookup; the real
  outage/recovery check passes without weakening its assertions.
- Jenkins needed explicit `-name` agent arguments and a writable `/workspace@tmp`
  sibling directory for durable shell tasks. The agent also needs the Buildx
  plugin for BuildKit and a Docker server certificate whose SAN contains its
  actual service name, `engine`. TLS verification remains enabled.
- Non-root Nginx on Kubernetes needs group access to its writable `emptyDir`
  volumes; the pod now sets `fsGroup: 101`.
- A preinstalled hosted kind binary was correctly reused, but the installer then
  checked a different path. Final version checks now resolve the active PATH.
- The initial kind node tag was unavailable. The configuration selects
  `v1.36.4` and its exact digest from the
  [kind 0.33.0 release](https://github.com/kubernetes-sigs/kind/releases/tag/v0.33.0).
- On the laptop, HashiCorp's release site and provider registry return an explicit
  regional access response. The CLI was extracted from the official digest-pinned
  OCI image. Local provider initialization remains blocked; no unofficial mirror
  or regional-access bypass was used. Successful hosted initialization does not
  remove this laptop limitation.
